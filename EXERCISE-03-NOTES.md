In `App.tsx`, apply `className="reading-goal-container"` to the wrapper around `ReadingGoal`. In `ReadingGoal.tsx`, import `ReadingGoal.css` and use `className="reading-goal-close"` on the close button. Add a separate `:hover` rule to change its background or foreground colour.

**Build-output observation:** Vite processes and bundles imported CSS into production assets under `dist/assets`. With plain CSS, the authored class names remain global and can affect any matching element in the application. Production output may be minified and combined; it is not necessarily one output file per source CSS file.

## 2. CSS Modules

A CSS Module is a CSS file conventionally named `ReadingGoal.module.css`. Import it as an object:

```tsx
import styles from "./ReadingGoal.module.css";

<div className={styles.readingCard}>...</div>
```

The CSS class is locally scoped to the module. Vite transforms local class names into generated names in the built CSS and JavaScript mapping. This reduces accidental class-name collisions between components.

### Migration analysis

In the earlier CSS approach, styles were written in separate CSS files and connected to components using class names. In CSS Modules, the component imports a module object and uses locally scoped class names, which helps prevent naming conflicts. In Tailwind, most visual styling is expressed directly in JSX through utility classes. This makes the component's layout and states visible next to its markup and reduces the need to maintain a separate component stylesheet. The trade-off is that JSX class strings become longer and developers need familiarity with Tailwind's utility vocabulary. Tailwind generates CSS for the classes it detects in source files, so the production CSS contains generated utility rules rather than a hand-written selector for every component.

## 5. Comparing plain CSS, CSS Modules, and Tailwind

### a. Main differences

Plain CSS uses normal selectors and a global cascade. CSS Modules use normal CSS syntax but scope class names to a module and expose them through an imported JavaScript object. Tailwind is a utility-first CSS framework: developers compose visual styles using predefined classes in markup, and the build process generates the CSS needed by detected classes.

### b. Benefits

- **Plain CSS:** standard web technology, flexible, no framework-specific class vocabulary, and suitable for small projects or bespoke styling.
- **CSS Modules:** familiar CSS syntax with component-level scoping; styles remain in separate files and can be organised around components.
- **Tailwind:** fast composition with reusable utilities, consistent design tokens, responsive and interaction variants, and less need to invent and name one-off classes.

### c. Downsides

- **Plain CSS:** global selectors can conflict, naming conventions need discipline, and large stylesheets can become difficult to maintain.
- **CSS Modules:** still require CSS files and class-name mapping; styles may be repeated across modules unless shared conventions or design tokens are created.
- **Tailwind:** JSX can contain many classes, custom designs may require learning its configuration and conventions, and dynamic class construction must be handled carefully so the build can detect the required classes.

### d. Personal preference — personalise before submission

For this exercise, I prefer Tailwind CSS for a small React component because I can see the layout and styling beside the JSX, make responsive changes quickly, and use consistent spacing and colour utilities. I would still choose CSS Modules for components with complex bespoke styling or when keeping markup especially concise is a priority. ## 6. Four ways to use SVGs in React

The course brief asks for the four approaches from the course book. The following are common approaches; verify that these names match the exact four presented in Chapter 4 before submitting:

1. **Inline SVG markup:** write the `<svg>` and its child elements directly in JSX. SVG attributes use JSX naming conventions, such as `strokeWidth`.
2. **SVG file as an image:** put the SVG in the public folder or import it as a URL and render it with `<img>`. This is straightforward, but internal paths are not directly controllable with React props or CSS selectors from the parent component.
3. **SVG as a CSS background:** use the SVG file in `background-image`. This is useful for decorative graphics, but it is not naturally exposed as meaningful image content to assistive technology.
4. **SVG imported as a React component:** use an SVG-to-React transformation tool such as SVGR (when configured for the build tool) so the SVG becomes a component. This supports component props and styling, but needs build tooling or an appropriate package.

| Approach | Pros | Cons |
| --- | --- | --- |
| Inline SVG | Full control, style with props/classes, no extra request | Adds markup to JSX |
| `img` with SVG file | Simple, reusable asset, browser caching | Harder to style internal paths dynamically |
| CSS background | Good for decorative imagery | Not semantic content; sizing/colour control can be limited |
| SVG as React component (SVGR) | Reusable, prop-driven, styleable | Requires configuration or transformation |

## 7. SVGs in the Reading Goal application

### a. Ways to embed the close icon

A close icon can be included as inline SVG markup, loaded as an SVG file through an `img` element, used as a CSS background for a decorative icon, or imported as a React component with an SVG transformation tool.

### b. Current implementation and justification

The close button currently uses inline SVG markup. This is a good fit for a small interactive icon because its stroke uses `currentColor`, its size is explicit, and Tailwind can control the surrounding button's hover and focus states. The SVG is marked `aria-hidden` because the button already has the accessible name “Dismiss reading goal”.

### c. Alternative implementation

The repository also includes `public/close.svg`. To try the external-file method, replace the inline SVG in the button with:

```tsx
<img src="/close.svg" alt="" aria-hidden="true" width="18" height="18" />
```

The inline version is easier to style internally and can inherit `currentColor` directly. The external image keeps SVG markup out of the component and can be cached as a separate asset, but styling its internal path from the button is less direct.

## 8. Sources of SVG icons

1. **Lucide:** a consistent open-source icon family with a React package. Icons are React components that render inline SVG, and imported icons can be tree-shaken. Recommended use: install `lucide-react`, import only the icons needed, and provide accessible labels on the containing controls.
2. **Heroicons:** a hand-crafted icon set from the Tailwind CSS team with a React package and outline/solid variants. Recommended use: install `@heroicons/react` and import a specific icon from the appropriate size/style entry point.
3. **Iconify:** a unified React component interface to a very large collection of icon sets. Recommended use: install `@iconify/react` and use a specific icon identifier; consider whether runtime loading from the Iconify API is appropriate for the application's offline, privacy, and performance requirements.

Check each icon's licence and attribution requirements before using it in a public or commercial project.
